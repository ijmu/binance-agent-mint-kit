# 调度说明（通用版）

本系统由若干定时环节协同运行，各环节只做自己的事、通过文件与登记册交接，不互相直接调用。下表只写节奏与职责；具体用什么调度器（cron / 任务平台）实现均可，按此节奏复刻即可。

| 环节 | 节奏 | 职责 |
|---|---|---|
| 增量扫描 | 每 15 分钟 | 按来源分层取数（热源约 14 分钟、温源 60 分钟、冷源 1440 分钟，未到期自动跳过）：发现新项目线索、刷新在板项目进度；新候选当轮完成核查接线（判重 → 源码验证 → 规则 10/11 筛查），通过的写入评分事实库待发布轮出分 |
| 整点发布 | 每小时整点（后续可放宽为每 2 小时） | 收尾核查、存活复核（OK / WARN / DEAD / ENDED）、100 分风险评分、更新内部工作台与公开库 PROJECTS.md（项目页 + 本轮变化） |
| 自动执行 | 每 2 小时 | 只打评分 ≥80 且配置为可执行、且钱包未打过的项目（每轮有上限）；到期自动领取押金/奖励；有可卖持仓且报价达标时自动卖出；每轮末尾跑一次 NFT 持仓跟踪 |
| 生态监控 | 每 30 分钟 | 三路发现（定点盯号、广场深搜、全量雷达）盯 NFT / 代币首发；动手前三项核验全过且满足纯 NFT 门槛（卖法 + 热度/进度）才直打，否则只记日志 |
| 关键词搜索 | 每 12 小时 | 按关键词组搜索新线索，产出线索包供增量扫描核查 |
| 渠道深挖 | 每日 20:00 | 找新的发现渠道/来源，只提议加入来源清单，不直接改扫描配置 |
| 每日成绩汇报 | 每日 21:00 | 只读汇报：今日新打/领取/卖出与 gas、累计花费与在押押金、已实现与未实现盈亏、钱包余额与持仓估值；不动钱、不交易 |
| 每日备份 | 每日清晨 | 把工作区（空间源码、目标文件、任务定义、脚本与纸面记录）打包推送到私有备份库；无变化不推 |

纪律：

- 发现与核查分离：增量环节不改公开内容，发布环节不做新发现。
- 执行环节只读发布环节定版的数据（评分与指令），不自己改分、不越门槛。
- 任何环节失败只记日志并在汇报时如实说明，不拿旧数据冒充新结果。
- 改节奏、改门槛、改上限属于规则变更，须经系统所有者拍板后才落地。
